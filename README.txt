==================================================

【安装】/【六项检查】/【一键转曲】/【已知限制】的完整说明见 README.md；
本文件自 v8.3 起只保留变更日志(首行版本号仍由发布流程读取)。

【版本】
v8.6 修复 + 提速: ① 重入锁——超时只是"前端不再等",ExtendScript 里的扫描仍在跑(单线程,
          停不下来),旧版此时按钮已恢复可点,再点会把 runPreflight() 排队**再跑一遍**
          (总耗时翻倍、两次结果先后覆盖渲染);现加 scanBusy,扫描期间忽略点击并提示
          "正在检查中，请稍候再试。"。
          ② JSON 序列化补 C0 兜底——esc 原来只转义 \r\n\t,文本框内容里若混入 \b / \f / \v
          等其他控制字符(0x00~0x1F),产出的 JSON 就是非法的,前端 JSON.parse 失败 ⇒
          parseResult 返回 null ⇒ **整轮结果作废**,面板只报"脚本执行失败";现统一转成 \uXXXX。
          ③ 出血口径修正——组的 geometricBounds 是纯几何量、**含隐藏子项**:可见组里若有
          隐藏子项越界,组级测量会把它的超出算进出血(每边取 max)⇒ 可能**漏报出血不足**
          与"隐藏内容不参与印刷统计"的口径相悖;现改为组级测量只作兜底(子项列表读不出来
          时才测),正常路径不再测组(可见子项本就各自测过,取 max 天然幂等)。
          ④ 提速与顺手项: Base64 解码改用宿主原生 atob(宿主没有时自动回退纯 JS 解码);
          文本框片段 pfSnippet 每帧只取一次(原最多 4 次);文字/图形叠印样本复用已读出的
          色值句柄,不再回读;内部去重键 _k 不再下发到前端(前端从不用它);一键操作
          (嵌入/转曲)也补上 20 秒"仍在继续"提示(原来大 PDF 栅格化期间 loading 一直转
          却毫无反馈)。判定阈值、样本口径与卡片文案一律不变。
v8.5 性能: 两处热路径优化(纯提速,判定口径/阈值/样本一律不变)——
          ① 缓存复用: 同一文字帧的 characterAttributes、同一图形的 fillColor/
             strokeColor/stroked 此前被分散重复读取(每帧约 5 次跨桥),现各读一次
             后全流程复用;油墨"总量求和"与"过浅分量判定"原为两次独立读取 CMYK
             分量,现合并为一次读取(每色 8 → 4 次),两处结论共用同一份原值。
          ② 字体表按需探测: 缺失字体检测原先把整张 app.textFonts 快照读进内存
             (每字 3 次跨桥读, N 可达 1800+, 重建时"可达秒级"),现改为只对
             文档实际用到的字体名(去重后 K≈5~30)逐个 app.textFonts.getByName
             探测,查不到才算缺失。三层保护确保不误报: (a) 加载时自检——若
             getByName 连首选字体都查不到,自动退回旧的整表快照; (b) 任一探测
             未命中即触发一次整表快照兜底仲裁; (c) textFonts.length 变化即清空
             探测缓存并重跑自检。
          实测(node 回归 outline/ink-align/sample-caps 全过): 真装连字符字体
          (如"阿里妈妈方圆体 VF")在按需探测下正常查到、不误报;缺失占位条目仍正确判缺。
v8.4 修复: 卡③「字体转曲」缺失字体漏报——旧判定只看"条目无 style 且 family 空/等于字体名",
          对**名中带连字符**的缺失字体(如 zihun105hao-jianyahei-Regular)整类漏报;
          新增第二判据「切分痕迹」: 占位条目的 family/style 恰好是字体名在**首个连字符**处
          硬切出来的(style=连字符后段, family=前段+空格+后段)即判缺失;真装字体 family 取自
          真实 name table(如"阿里妈妈方圆体 VF"),不受影响。真机 1810 字体实测: 命中 1、误报 0。
v8.3 新增: 叠印(Overprint)检查——卡6 标题改「油墨 · 叠印 · 描边粗细」,在"色版1~4%"与

          · 文字侧只能走**字符级** textRange.characterAttributes.overprintFill/overprintStroke
            (真机 AI 28.0.0 上 TextFrame 的 pageItem 级同名属性不存在);
